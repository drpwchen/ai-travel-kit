# 能力對照：接了什麼，AI 就能多做什麼

> 給 AI：先確認你自己現在有哪些能力（`START.md` §1.5），再用這張表。
> - 有的能力**直接用**，不用先問；動到對外的事（寄信、送表單、付款、取消）仍然照 `START.md` §4 規則 4，由使用者自己送出。
> - 某件事接上一個工具就能做得更好時，**一句話提一次**「接上 ○○ 我就能直接 ××」，附上怎麼接（≤3 步）；使用者沒興趣就照不接的做法繼續，不要每次都推。
> - 只提**使用者正在用的平台**做得到的；不確定平台有沒有這個功能就說不確定，請他看設定頁。
> - 以下為 2026-10 查的狀態（🔄 各平台功能、方案、地區限制變得很快，提之前能查就再查一次）。

## 1. 能力分級

| 等級 | 你有什麼 | 能做的事 | 例子 |
|---|---|---|---|
| 0 | 只能對話 | 訪談、建總檔、排行程（用總檔的速度）、起草信件、整理條款重點 | 任何 AI |
| 1 | 能上網 | 查天氣、班次、官網開放時間與票價，標「已查證」 | 多數網頁版 AI 都有搜尋 |
| 2 | 能讀使用者上傳的檔 | 讀合約、保險條款、確認信 PDF；讀記帳匯出、GPS 軌跡 | 上傳檔案 |
| 3 | 接了使用者的帳號 | 從信箱找出所有訂單、整理成清單或列印包；讀雲端硬碟的總檔；讀行事曆 | Gmail、Google 雲端硬碟、行事曆連接器 |
| 4 | 能定時自己跑 | 每天傍晚查極光機會、取消期限前查天氣給建議、出發前一天提醒線上報到 | ChatGPT 的排程任務；Claude Code／Codex＋電腦排程 |
| 5 | 能執行程式、操作檔案 | 讀照片 EXIF 算出每個點停多久、批次下載確認信、做全家共用的行程網頁、把導覽稿轉成語音 | Claude Code、Codex、ChatGPT／Claude 的程式執行 |
| 6 | 能操作瀏覽器 | 登入網站改資料、填客服或理賠表單（最後一步交給使用者按） | 有瀏覽器操作功能的 agent |

## 2. 想做的事 → 要接什麼

| 想做的事 | 最低需要 | 怎麼接（🔄 2026-10） | 沒有時的替代 |
|---|---|---|---|
| 依自己的速度排行程 | 0 | — | — |
| 查天氣、班次、景點官網 | 1 | 打開對話的搜尋／網路功能 | 給使用者官方查詢入口與要核對的項目 |
| 讀合約、條款、確認信 | 2 | 上傳 PDF 或截圖（先遮掉訂位代號、卡號） | 請使用者貼關鍵段落 |
| 找出所有訂單、做列印包 | 3 | Claude：設定 → 連接器 → Gmail（Pro 以上）；ChatGPT：設定 → 應用程式（Apps）→ Gmail；Gemini：應用程式連結 → Gmail | 請使用者在信箱搜尋「確認」「booking」，把清單貼回來（只貼名稱與日期） |
| 總檔存在雲端，每次自動讀 | 3 | Google 雲端硬碟連接器，或平台的 Project／Gem 知識檔（`START.md` §5） | 每次對話上傳總檔 |
| 定時提醒、自動查天氣 | 4 | ChatGPT：在對話裡說「每天傍晚 6 點幫我查…」建排程任務（免費版有數量與頻率限制）；Claude Code／Codex：請 AI 寫小程式＋電腦排程 | 在這趟檔的待辦寫日期，使用者自己設手機提醒 |
| 從照片或 GPS 算出自己的速度 | 2 或 5 | 見 §3 | 使用者回想，標「本人說」 |
| 全家共用的行程網頁、語音導覽 | 5 | Claude Code／Codex（`guide/trip-website.md`） | 平台的互動頁面（Artifacts、Canvas）或共用雲端文件 |
| 填網站表單、改帳戶資料 | 6 | 瀏覽器操作 agent | 起草要填的內容，使用者自己貼 |

## 3. 你的速度從哪來

排行程最需要的是「這個人實際多快」，網路上的建議時間通常太樂觀。來源依準確度：

| 來源 | 準不準 | 怎麼拿給 AI |
|---|---|---|
| 本人記得的時間 | 最準（有記的話） | 直接講 |
| 照片的拍攝時間 | 準：每張照片都有時間，多數有位置 | **網頁版**：手機相簿點開照片看「資訊」，把每個點第一張和最後一張的時間唸給 AI（上傳照片時平台可能剝掉時間與位置資訊，不要依賴）。**Claude Code／Codex**：把照片資料夾給 AI，請它讀 EXIF 批次算 |
| 運動紀錄（Strava、Garmin、Apple 健康、手錶） | 爬山、騎車最準：有爬升與停留 | 匯出那次活動的 GPX 檔上傳；或直接截圖活動摘要（距離、爬升、時間） |
| 手機定位紀錄（Google 地圖時間軸） | 位置可信，時間可能差十幾二十分鐘 | 在手機上匯出時間軸資料上傳，只看大概 |
| 記帳 App 的時間 | 只能推「幾點在哪裡吃飯」 | 匯出時一併給 |

- 優先順序：**本人記得的 ＞ 照片 ＞ 運動紀錄 ＞ 定位**。
- 第一趟還沒有實測：用訪談的自評加 `guide/baselines.md` 的預設值，標「估計」。回來後照 `phases/after.md` §4 換成實測。
- 照片和軌跡含精確位置：只在跟 AI 的私人對話或自己的電腦上用，不要放進公開的地方。

## 4. 存在哪裡：一律私人

總檔寫了你和同行者的習慣、健康限制、常去的地方，==只存在私人的地方==。

| 你用的是 | 存法 | AI 能幫你做到哪 |
|---|---|---|
| 網頁版／App | 平台的 Project、Gem（`START.md` §5），或自己的雲端硬碟（不共用） | AI 產出檔案，你上傳一次；接了雲端硬碟連接器的話，AI 能直接讀 |
| Claude Code／Codex | clone 這個工具箱，總檔放 `my/`（不會被 git 追蹤）。想備份或換電腦用：請 AI 把 `my/` 推到你自己的 **private** repo | AI 可以全部代辦（見下方） |

**不要 fork 這個 repo 來放自己的資料**：GitHub 上公開 repo 的 fork **一定是公開的**，不能改成私人；
放進去的總檔、行程、健康限制任何人都看得到。要用 GitHub 就建一個**新的 private repo**。

給 Claude Code／Codex（使用者說要備份、換電腦用、或跟旅伴共用時才做）：
1. 先確認使用者有 GitHub 帳號、已登入 `gh`（`gh auth status`）；沒有就教他 `gh auth login`，這步要他自己做。
2. 在 `my/` 裡 `git init` 並做第一個 commit，再用 `gh repo create <名稱> --private --source my --push` 建私人 repo 並推上去。
   ==建之前跟使用者確認名稱與「私人」==；指令裡沒有 `--private` 不要執行。
3. 建好後用 `gh repo view <名稱> --json visibility` 確認是 `PRIVATE`，再告訴使用者。
4. 之後每次更新總檔，在 `my/` 裡 commit＋push；工具箱本身照常 `git pull` 更新，兩邊互不影響。
5. 跟旅伴共用這趟檔：在那個 private repo 加旅伴為 collaborator，只共用這趟檔所在的 repo，不要把總檔一起共用（可以把這趟檔另外建一個 private repo）。
