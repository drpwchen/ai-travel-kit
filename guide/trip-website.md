# 全家一起看的行程網頁

> 給 AI：多人同行（尤其有長輩）時，一個網址就能找到所有資訊，比資訊散在聊天群組裡好用很多。
> 但做網頁要花力氣，先用 §3 判斷值不值得。使用者不會寫程式的話，從「每日行程表」一個頁面開始就好。

## 1. 一句話

**一個網址，首頁永遠只放「這個階段要用的東西」，過了就收進封存，不刪。**
行前是說明書加清單，旅途中是「今天與明天」，出事時是理賠頁，回來後是回顧加花費。

## 2. 前中後各放什麼

| 階段 | 首頁第一屏 | 其他頁 |
|---|---|---|
| 規劃 | 方案：一天一行＋為什麼去、大概花多少 | — |
| 行前（出發前一個月） | 倒數＋「主辦統一處理 vs 各自準備」兩欄待辦 | 共用行李清單、行前小考、保險與出事時要留什麼、自駕須知、住宿資訊、緊急電話、相簿上傳教學 |
| 出發／回程日 | 集合時間、早餐時間分開寫；機場須知（樓層、報到截止、貴賓室、轉機會合點） | — |
| 旅途中 | 今天與明天：路線、停靠點（一鍵導航）、廁所、天氣重點 | 接下來、走過的日子、沒去成的、相簿 |
| 出事 | 理賠頁放第一個；期限條 | 每個人自己的步驟、進度勾選、信件範本 |
| 回來後 | 回顧：路線地圖＋每天實際走過的卡片 | 花費分攤、相簿、封存（行前的東西全部收這裡） |

同一個網址、跟著階段換首頁，家人的書籤不用改。

## 3. 依人數取捨

✅ 要做　△ 看情況　❌ 不做

### 必備模組檢查表（做網頁的人上線前逐項對照）

常見的漏法：上表有列「共用行李清單」，但做的人只照「先上每日行程、行前再上其他頁」的步驟走，沒有一步要求拿表逐項對，結果整個行李分頁漏掉，直到出發前才有人發現。所以==上線前（規劃版上線、行前一個月、出發前一天，各一次）把下列每項標「做了」或「不做＋一句理由」==，不要靠記憶：

| # | 模組 | 缺了的後果 |
|---|---|---|
| 1 | 每日卡片＋一鍵導航 | 手機上要自己複製地址去查 |
| 2 | 住宿卡 | 到了才翻信找地址 |
| 3 | 共用行李清單 | 共用品沒人認領，出發前才發現 |
| 4 | 要先訂清單 | 熱門景點、餐廳訂不到 |
| 5 | 會議／固定行程 | 報到、報告時段被其他安排蓋掉 |
| 6 | 緊急電話＋就醫 | 出事時才找電話 |
| 7 | 語音介紹 | 依人數取捨，見上表 |
| 8 | 花費分攤、理賠頁 | 視人數：兩人行不做網頁，多人行前先講好規則 |

「不做」不是預設值，要寫得出理由（例：兩人行，花費分攤用記帳 app 就好）。把對照結果記在這趟檔；請 AI 或別人代做網頁時，把「上線前逐項對照這張表」寫進完成條件。

## 4. 經驗

- **行李清單一個月前就給大家**，太晚大家沒時間買。
- **行前小考**：只考家人自己要準備、要注意、有趣的東西；不要考主辦處理的後勤（轉機、票價）。長輩真的會去讀。
- **給長輩看的文字**：一天一行＋為什麼去；AI 寫的長文他們沒耐心看。
- **理賠頁的骨架行前就備好**（每人的保單與信用卡附險、各管道期限、出事時要留什麼），不要等出事才從零做。
- **花費規則出發前講好**：記帳時就寫「誰付、幾人份」；請客算不算分攤先講好。
- 旅途中：家人討論完、有結論，才去改網頁上的隔天行程。
- 時刻表貼出前核對兩個方向（去程、回程最容易互相抄錯）。
- 一份內容只放一處：網頁和紙本各抄一份，改了一邊一定會忘另一邊。

## 5. 隱私紅線

- 網頁就算有密碼，也當作「別人可能看得到」：==不放證件號碼、訂位代號、訂房 PIN、票價、卡號==。
- 電子機票、收據這類檔案不要放在公開的網頁資料夾。共用的雲端文件、資料夾也一樣：確認信與單據放各自的私人資料夾。
- 門鎖密碼、訂房 PIN 不放在任何網頁、共用文件或 AI 對話；需要時主辦私訊給同行者。
- ==前端 JavaScript 的密碼只是擋路人，不是真的保護==：原始碼裡的內容誰都看得到。網頁上只放不敏感的行程資訊；要真正限制存取，要用有伺服器端登入控管的服務，並用未登入的瀏覽器實測。

## 6. 怎麼做（看使用者的能力）

| 使用者 | 做法 |
|---|---|
| 不寫程式 | 請 AI 產出一份每日行程表（文件或試算表），分享連結給家人；行李清單用共用的待辦清單 app |
| 會一點點 | 先用共用文件（Google 文件、Notion）或旅遊 App 就好，旅途中手機好改；真的想要網頁，再請 AI 產出單一 HTML 檔放到免費靜態網站（只放不敏感的資訊） |
| 會寫程式 | 靜態頁＋一個小後端，存需要多人一起改的東西（行李勾選、小考成績、理賠進度） |
