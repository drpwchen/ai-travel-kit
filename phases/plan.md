# 階段：規劃一趟（出發前 6–1 個月）

> 給 AI：先讀使用者的總檔。沒有總檔就先做 `interview.md` 快速版。

## 1. 先收這趟的基本資料（一次問完，五題內；總檔或對話裡已經知道的不要再問）

1. 去哪裡？（還沒決定也可以，給幾個候選）
2. 大概日期、幾天？日期能不能動？
3. 跟誰？（跟總檔 §8 的同行者比對；有同行者就做 §4 的問卷）
4. 這趟最想要的一件事是什麼？（例：看極光、吃、陪長輩、開會）
5. 已經訂了什麼？

## 2. 產出「這趟的一頁摘要」

```markdown
# ○○ YYYY-MM
- 日期／天數／跟誰
- 這趟最想要的：
- 這趟的限制：（從總檔 §5、§8 帶過來）
- 已訂：
- 未訂（依急迫排序）：
- 這趟要特別注意（從總檔 §2 我的提醒挑相關的）：
```

## 3. 依日期列待辦

照 `guide/timeline.md`，**用實際日期**（不是「出發前 3 個月」）列出：

- 這週要做的（3–7 件）
- 有硬期限的（熱門門票開賣日、免費取消期限、會議早鳥、特殊餐截止）→ 換算成日期，請使用者放進行事曆
- 其他的等時間到了再講

## 4. 同行者偏好整理（有同行者時）

照 `interview.md` §I 產出問卷，收回答案後，整理成三欄：大家都想要／部分人想要／有人不要。不同的地方給折衷方案，不要只選一邊。

## 5. 景點與行程

1. **先列候選**，每個候選點一行：是什麼、為什麼適合這群人、要多久、難易度（距離／爬升）、要不要預約。
2. **查證再排**：開放日與時間、票價、要不要預約、近期有沒有整修閉館。
   - 從官網確認的標 ✅（附網址與查詢日期）；第三方來源（部落格、旅遊網站）標 ⚠️。
   - 不能上網就全部標「待查證」。
3. **讓使用者挑**：每個候選點給三個選項「一定要／有空再去／不去」。
   可以做成一份清單請他回覆，也可以（平台允許時）做成一頁可點選的小網頁，最後「複製結果」貼回對話。
4. **排每日行程**：用總檔 §3 的速度；第一天抵達日放輕；換住宿日不排大行程；每天留備案（下雨版）。
   每天一行「為什麼這樣排」，給同行的長輩看得懂。

## 6. 訂東西的提醒

- **先查所有人的護照效期**（回程日起 ≥6 個月），快到期現在就去換；自駕再查駕照。
- 機票：用附旅遊不便險的卡刷全額；==刷之前確認卡附的險保到哪些人==（常只保持卡人、配偶、未成年子女，同行的父母通常不算）；兩段不同訂位代號的轉機風險自己扛（前段延誤後段不負責），轉機至少留 3–4 小時。
- 住宿：寫下免費取消期限（換算成台灣時間）；住超過 5 天找有洗衣機的；吃素或有飲食限制優先有廚房。
- 租車：每位駕駛的證件效期；至少登記兩位駕駛；另買的車損險被保人要是實際開車的人。
- 保險：機票訂好就決定要不要另買旅遊不便險；越早保越好（颱風警報、罷工預告發布後才保通常不賠）。出發前一個月再確認保單細節。
- **日期看自然現象的旅行**（櫻花、紅葉、極光、雪季）：預測常在出發前 1–3 個月才公布。住宿先訂可免費取消的；
  把「預測公布日」和「免費取消期限」一起放進行事曆；機票等日期大致定了再刷，或選可改期的票。

## 7. 要不要做全家一起看的行程網頁

三人以上、尤其有長輩才值得，見 `guide/trip-website.md`。兩個人的旅行，一份清楚的每日行程表就夠。

## 8. 更新總檔
